# Политика конфиденциальности Aurora

**Дата последнего обновления: 2026-11-09**

> **Дисклеймер.** Настоящий документ создан для сервиса Aurora и не является юридической консультацией. Это некоммерческий, любительский (hobby) проект одного оператора. Документ носит информационный характер и не заменяет консультацию юриста.

## 1. Кто мы

Aurora — некоммерческий веб-сервис для прослушивания собственной музыки, доступный по адресу `https://aurora-api-3.onrender.com`. Сервисом управляет единственный оператор (физическое лицо, не компания). Связаться с оператором можно через GitHub-репозиторий проекта (issues).

## 2. Какие данные мы обрабатываем

### 2.1. Учётная запись (email + пароль)

Если вы регистрируете учётную запись, мы храним:

- **адрес электронной почты** — как идентификатор входа;
- **хэш пароля** (Argon2). Пароль в открытом виде **никогда** не хранится и не логируется.

### 2.2. Cookie-идентификаторы

Сервис использует случайные идентификаторы в cookie. В базе данных хранятся **только их SHA-256-хэши**, а не сами значения (см. таблицу cookie в разделе 6).

### 2.3. Подключённые OAuth-аккаунты (Google / YouTube Music)

Когда вы подключаете YouTube Music через Google, мы сохраняем:

- идентификатор аккаунта провайдера (`subject`);
- отображаемое имя и URL аватара;
- список предоставленных разрешений (scopes);
- OAuth-токены — **в зашифрованном виде** (AES-256-GCM; ключ шифрования хранится только на сервере).

Пароль вашего Google-аккаунта никогда не проходит через сервис: вход выполняется на стороне Google.

### 2.4. Музыкальные данные

- метаданные треков и плейлистов (название, исполнитель, обложка, текст песни, перевод — только сохранённые вами);
- содержимое вашей библиотеки и плейлистов.

### 2.5. IP-адреса

IP-адрес используется **только в оперативной памяти** для защиты от злоупотреблений (rate limiting) и **никогда не сохраняется** на диске и не логируется.

## 3. Где хранятся данные

Данные хранятся на серверах Render (https://render.com) в одной инстанции, в базе данных SQLite на постоянном диске. Мы не раскрываем конкретный регион — используйте информацию Render о расположении своих дата-центров.

## 4. Срок хранения

| Данные | Срок |
| --- | --- |
| Учётная запись (email, хэш пароля) | до запроса на удаление |
| OAuth-привязка (grant) | до отключения в настройках — строка удаляется вместе с токенами |
| OAuth-токены | до отключения провайдера или повторного подключения (перезаписываются) |
| Сессии и транзакции OAuth | удаляются автоматически по истечении (минуты/часы) |
| Библиотека, плейлисты, тексты | до удаления пользователем или аккаунта |

## 5. Третьи стороны

- **Google (OAuth / YouTube Music API)** — при подключении аккаунта. Обработка данных на стороне Google описана в https://policies.google.com/privacy.
- **LRCLIB** (https://lrclib.net) — публичный API без ключей, для поиска текстов песен (передаются название/исполнитель/альбом трека).
- **Сервис перевода** (внешний LibreTranslate-эндпоинт) — при нажатии «Перевести» текст песни передаётся в настроенный сервис перевода. Не пользуйтесь переводом, если не хотите отправлять текст.
- **Никакой** аналитики, трекеров, рекламы или продажи данных нет.

## 6. Cookie

| Имя | Срок | Назначение |
| --- | --- | --- |
| `__Host-aurora_auth` | 30 дней | идентификация вошедшего пользователя (email+пароль) |
| `__Host-aurora_user` | 180 дней | постоянный анонимный идентификатор для привязки OAuth-аккаунтов |
| `__Host-aurora_session` | 8 часов | сессия (в т.ч. защита от CSRF) |
| `__Host-aurora_csrf` | сессия браузера | CSRF-токен (читается скриптом) |

Все cookie — `HttpOnly` (кроме CSRF), `Secure`, `SameSite=Lax`. Случайные значения cookie в базе хранятся только как SHA-256-хэши.

## 7. Ваши права

- **Отключить провайдер** (например, YouTube Music) можно в Настройках — привязка и токены удаляются немедленно.
- **Удалить учётную запись и данные** — по запросу через GitHub issues.
- Данные в рамках одного аккаунта не передаются никому, кроме перечисленных в разделе 5 сервисов.

## 8. Изменения

При изменении политики дата в заголовке обновляется; существенные изменения анонсируются в репозитории проекта.
