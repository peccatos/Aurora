# Aurora Web — план веб-версии

_Статус: черновик плана (после kernel/shell split, ADR 0005).
Основа: `aurora-kernel` — ядро без UI-зависимостей; веб — третья оболочка
рядом с десктопом (Tauri) и будущими сторонними плеерами.
Идеи фич вокруг сервисной надстройки — раздел 6 (из заметки владельца,
`заметки-фичи.txt`)._

---

## 0. Честная рамка (до строчки кода)

Веб-версия Aurora — тот же плеер, которому верят, но с честно
зафиксированными ограничениями платформы. Ни одно из них не прячется:

| Свойство | Десктоп | Веб |
|---|---|---|
| Bit-perfect | измеряется (WASAPI exclusive + loopback) | **N/A (browser audio path)** — статус репортится честно, вердикт не выдаётся |
| Трансформации | репортятся все | репортятся все (это про наш DSP, не про ОС) |
| VST3 | изолированные хелперы | **нет** (нативные DLL в браузере невозможны); путь: AudioWorklet-плагины (свои), позже — возможно WAM |
| Файлы | скан папок, SQLite | File System Access API / drag-n-drop; библиотека — IndexedDB/OPFS |
| Media-клавиши | global-shortcut | MediaSession API (работает даже лучше) |

Правило: если браузер не даёт доказать — мы пишем «не проверяемо здесь»,
а не молчим. Слава ADR 0002 переносится в веб.

## 1. Архитектура (ADR 0006, оформит решения)

```
aurora-kernel (Rust, без изменений по логике)
    │  компилируется в WASM через отдельный wasm-target
    ▼
aurora-web (новый крейт-оболочка, wasm)
    │  - wasm-bindgen API: класс WebKernel (методы = методы PlayerKernel)
    │  - события ядра → JS-callback'и (EventSubscribers уже есть)
    ▼
frontend/ (тот же TypeScript, расширенный)
    │  - invoke-слой становится тройным:
    │      TauriInvoke  (десктоп, как сейчас)
    │      WasmInvoke   (веб: вызов WebKernel напрямую, без IPC)
    │      (HttpInvoke  — резерв под серверную надстройку, раздел 6)
    │  - роутер/страницы/стили общие
    ▼
index.html + Vite (та же сборка; таргет web добавляется в vite config)
```

Ключевые решения:
- **Ядро локально, сервисы опционально.** Плеер работает без сети
  (декодинг/DSP/библиотека — wasm на клиенте). Сервисная надстройка
  (раздел 6) — подключаемые модули, ядро их не знает.
- **API-слой как интерфейс.** В `frontend/src/` появляется `invoke.ts`
  с реализациями под платформу; страницы продолжают звать
  `invoke("deck_load")`, не зная, где работают. Это и есть граница
  ADR 0005 на практике.
- **Та же библиотека домен-типов.** DTO ядра сериализуются одинаково.

## 2. Что переносится из ядра (порядок = приоритет)

### Волна 1 — воспроизведение (ядро MVP)
1. **Декодер** (`aurora-decoder`, Symphonia → wasm): FLAC/WAV/MP3/…
   в PCM-чанки. Symphonia компилируется в wasm (чистый Rust).
2. **DSP** (`aurora-dsp`): EQ/реверб/speed/ReplayGain в AudioWorklet.
   Бинарь worklet'а = тот же крейт `aurora-dsp` под target
   `wasm32-unknown-unknown`, процессинг фреймов тем же кодом, что на
   десктопе. Один код — одна честность.
3. **Очередь** (`queue.rs` ядра): логика advance/rewind — уже shell-free,
   заворачивается как есть.
4. **Спектр/вэйвформа**: FFT (rustfft) — уже в ядре, на воркере;
   в вебе — в том же AudioWorklet.
5. **A/B loop, seek** — методы ядра, работают поверх 1–2.

### Волна 2 — библиотека и DJ
6. **Хранилище**: IndexedDB (объекты Track/Playlist — те же DTO).
   SQLite-wasm в OPFS — опция «если понадобится масштаб» (не на старте).
7. **BPM-детектор** (`aurora-decoder::tempo`): чистый Rust + rustfft —
   компилируется как есть. Ленивое измерение при загрузке на деку.
8. **DJ-деки**: два AudioWorklet-потока + кроссфейдер (кривая уже в
   `decks.rs` — equal-power, фикс этой сессии). Jog-волны, хот-кью.
9. **Плейлисты**: импорт/экспорт (M3U/PLS/Spotify/CSV — `playlist_io.rs`
   чистый, переносится). Файловый IO — через Blob/File API.
10. **Watch библиотеки**: **нет в вебе** (нет событий ФС) — кнопка
    «пересканировать папку» через File System Access API.

### Волна 3 — что осознанно НЕ переносится
- VST3-хостинг (нативность). UI плагинов скрывается на веб-таргете.
- WASAPI exclusive / loopback-verify → страница «Bit-perfect» честно
  показывает «N/A в браузере».
- Глобальные хоткеи за пределами вкладки (MediaSession покрывает
  транспорт).

## 3. Пошаговый план волны 1 (первый milestone)

| # | Задача | Критерий готовности |
|---|---|---|
| 1 | `cargo build -p aurora-kernel --target wasm32-unknown-unknown` | ядро собирается (cpal/symphonia/wasm-гейты) |
| 2 | Крейт `aurora-web`: wasm-bindgen обёртка `WebKernel` | из JS: `new WebKernel().playTrack(path)` |
| 3 | `frontend/src/invoke.ts`: интерфейс + Tauri/Wasm реализации | tsc зелёный, десктоп не сломан |
| 4 | Декодинг одного FLAC в PCM через Symphonia-wasm | `decodeFile(file) → AudioBuffer` |
| 5 | AudioWorklet на `aurora-dsp`-wasm: EQ live | слайдер EQ меняет звук играющего трека |
| 6 | Очередь + play/pause/next + статус с трансформациями | мини-плеер работает в браузере |
| 7 | Спектр (16 полос) + вэйвформа | страница Player живая |
| 8 | Хостинг: GitHub Pages на этот же репозиторий | `https://peccatos.github.io/Aurora/` |

После волны 1: деки + IndexedDB-библиотека (волна 2), потом сервисные
фичи (раздел 6).

## 4. Известные риски (фиксируем заранее)

1. **cpal в ядре.** Ядро тянет `aurora-audio` (CPAL — нативный звук).
   Решение: в wasm-таргете `aurora-audio` заменяется интерфейсом вывода —
   ядро уже так устроено после feature-гейтинга `win-wasapi` (сессия
   03.11): завести feature `web-audio` с тем же паттерном. Выводом в
   браузере владеет AudioWorklet, а не CPAL.
2. **Размер wasm.** Symphonia «all» фич — тяжело. Ограничить фичи до
   lossless+mp3 на старте, остальное — по требованию (lazy-подгрузка
   кодеков — отдельные wasm-модули).
3. **SharedArrayBuffer** нужен для многопоточного DSP в worklet —
   требует COOP/COEP заголовков на хостинге (GitHub Pages умеет через
   `_headers`). Fallback: однопоточный worklet (медленнее, честно
   репортим задержку).
4. **Файлы**: перезагрузка страницы = потеря доступа к папке (это
   браузер, не мы) — библиотека в IndexedDB сохраняет метаданные,
   доступ просится заново. Честно в UI.

## 6. Сервисная надстройка — фичи вокруг ядра

_Из заметки владельца. Принцип: всё это — модули НАД ядром, не в ядре.
Ядро остаётся честным локальным плеером; надстройка добавляет сетевые
сервисы и может быть выключена целиком без потери базового функционала._

### 6.1 Тексты песен с переводом (Genius)
- Текст текущего трека онлайн с genius.com, синхронно с
  воспроизведением (прокрутка по таймкодам).
- Переключение языка перевода на лету: включил Канье — читаешь на
  английском, переключил — читаешь на русском (панель языков).
- Технически: сервис-модуль (HTTP), кэш текстов в IndexedDB,
  офлайн-фолбэк на закэшированное.
- Риски: Genius API требует токен; перевод — внешний сервис (выбор
  провайдера при реализации). Вкладка «Lyrics» на странице плеера.

### 6.2 Выгрузка с аккаунтов (VK / Яндекс Музыка / Spotify / Сбер Звук /
Apple Music)
- Импорт лайков/плейлистов/библиотеки по экспорту аккаунта: Spotify и
  Apple дают официальные экспорты; VK/Яндекс/Сбер — через инструменты
  экспорта или интеграции.
- Треки НЕ скачиваются нелегально: выгружаются МЕТАДАННЫЕ → матчинг с
  локальной библиотекой (механизм уже есть из playlist-import) →
  недостающее показывается списком «найди и добавь сам».
- Так остаёмся на легальной стороне: Aurora — плеер и органайзер, не
  загрузчик.

### 6.3 Совместные плейлисты
- Делиться плейлистом: экспорт M3U8 уже есть; следующий шаг — короткая
  ссылка с JSON-снимком плейлиста.
- Совместное редактирование: приглашение по ссылке-токену, участники
  вместе грузят треки (например, под предстоящую тусовку).
- Технически: первый настоящий серверный компонент (WebSocket-синк,
  CRDT-список треков — порядок и добавления сливаются без конфликтов).
  Сервер минимальный: хранение + relay. Ядро не меняется.
- Open-вопрос: свой хостинг vs готовый бэкенд — решить при старте.

### 6.4 Preview отрывков
- Послушать отрывок песни в отдельной вкладке (превью) до добавления в
  библиотеку/плейлист — с тем же честным DSP.
- Источник: легальные превью-API сервисов (Spotify/Apple/iTunes
  отдают превью-URL). Снова — надстройка, не ядро.

### 6.5 «Функционал YouTube Music» — что именно берём
Идеи, не реализация:
- Умные радио/автогенерация очереди от трека (по BPM/жанру из наших
  метаданных — BPM-детектор уже в ядре!);
- Экран «сейчас играет» крупно, с текстом песни (6.1);
- Лента «продолжить слушать» (история прослушиваний, локально);
- Поиск по библиотеке с опечатками (fuzzy) — чисто локально.
- Каждая идея отдельно оценивается: что в ядро, что в надстройку.

### 6.6 Порядок надстройки (после волн 1–2)
1. Lyrics + перевод (самостоятельная ценность, внешний API);
2. Preview (маленький шаг, внешний API);
3. Smart-queue/радио (локально, на наших данных — без сети!);
4. Share-плейлист ссылкой (экспорт → мини-сервер);
5. Совместное редактирование (сервер + CRDT — самый большой);
6. Импорт метаданных с сервисов (матчинг уже есть).

## 7. Дизайн веб-версии: YouTube Music один-в-один

_Решение владельца (03.11): дизайн-основа — YouTube Music, максимально
близко к оригиналу, включая красный акцент._

### Токены (YTM)
- Фон `#030303`, карточки/панели `#212121`, hover `#272727`
- Текст `#FFF` (первичный) / `#AAA` (вторичный) / `#909090` (третичный)
- Акцент: **красный `#FF0033`** (кнопки-play, активные состояния, прогресс)
- Типографика: Roboto (400/500/700), крупные заголовки «сейчас играет»
- Формы: круглые кнопки-иконки, карточки 8px-радиус, тени минимальны

### Layout — два сразу
- **Десктоп-браузер**: левый сайдбар (Home / Explore / Library + плейлисты),
  контент — горизонтальные ряды карточек (как ленты YTM), снизу плеербар:
  превью слева, транспорт по центру, очередь/прогресс справа. Полноэкранный
  «сейчас играет» по клику на превью.
- **Мобильный** (<=768px): сайдбар → нижние табы (Home/Explore/Library),
  мини-плеер над табами, свайп/тап разворачивает полноэкранный плеер
  (большая обложка, текст песни — раздел 6.1 ляжет сюда).

### Соответствие экранов
| YTM | Aurora Web |
|---|---|
| Home (ряды карточек) | `#/home` (новый) |
| Explore | `#/library` (поиск, фильтры) |
| Library | `#/library` → плейлисты полноэкранно |
| Плеербар + разворот | плеербар + fullscreen «сейчас играет» |
| Деки | `#/decks` — сохраняем (у YTM аналога нет; стиль под YTM) |

Реализация: отдельный CSS-слой `styles/ytm.css` (токены + компоненты) в
ветке веб-таргета фронтенда; десктопный Tauri-UI сохраняет швейцарский
минимализм Рамса — это две оболочки, два стиля (ADR 0005).
