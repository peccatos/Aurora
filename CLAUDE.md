# Aurora — правила для агента

## КРИТИЧЕСКОЕ ПРАВИЛО: запрет циклов команд ( burn guard )

ИНЦИДЕНТ: агент сжёг ~100 млн токенов, повторяя неработающую команду
с бессмысленными вариациями путей (~100 раз подряд `cd <битый путь>`).
Это стоило пользователю денег и времени. НИКОГДА БОЛЬШЕ.

ЖЕЛЕЗНЫЕ ПРАВИЛА:

1. **Две попытки максимум.** Если одна и та же команда упала дважды —
   СТОП. Не пробуешь третий вариант той же команды. Анализируешь причину
   и идёшь другим путём (другой инструмент, другой подход).

2. **Падение команды с `unexpected EOF` или `syntax error` = сломался
   сам вызов, не проект.** Это значит: строка команды содержит незакрытую
   кавычку или спецсимвол. Лечится переписыванием ВЫЗОВА через Write-файл
   (script.py) или упрощением команды до однострочника. НЕ повторением.

3. **Никогда не повторять команду, которая уже вернула ту же ошибку.**
   Особенно `cd`. Особенно с вариациями. Ошибка `cd` означает только одно:
   следующая команда должна начинаться с корректного `cd` в начале
   строки — проверить путь через `ls` перед сложной командой.

4. **Перед любой многострочной командой с кавычками/скобками** — пиши её
   в файл через Write (например `C:/Users/madei/AppData/Local/Temp/patch.py`)
   и запускай `python <файл>`. Bash-heredoc с питоном — источник
  _EOF-ошибок; файл надёжнее.

5. **Если почувствовал, что повторяешься** (третий однотипный вызов) —
   остановись и сообщи пользователю: «застрял на X, меняю подход на Y».
   Молчаливые повторы запрещены.

## Стиль работы в этом проекте

- Команды — короткие, по одной, с проверкой результата перед следующей.
- Массовые правки кода — только через python-скрипт из файла (Write → run),
  не через sed с экранированием и не через heredoc.
- Патчи большого объёма текста — Write в файл-скрипт, один запуск, проверка.
- Не коммитить без прогона: fmt + clippy + test workspace.
- Коммит-месседжи уже установлены (Co-Authored-By: Claude <noreply@anthropic.com>).
